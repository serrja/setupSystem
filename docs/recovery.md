# Recovery

Open History to identify an unfinished operation. Recover operation requests readback from the executor recorded in its confirmed snapshot. A running step may already have changed its resources. An unanswered request or missing receipt requires an observation before another mutation.

Verified resources can enter the ownership ledger. Uncertain reservations stay with the operation. Inspect an integration's own documentation for its native recovery procedure. Select and confirm a separate recovery plan before applying further changes.

For a completed local file action that declares rollback, choose **Restore files**. The original executor checks its recorded file identities, fingerprints and backups. Review the reversed file changes and confirm the separate operation. A later edit blocks restoration and remains available to its owner.
