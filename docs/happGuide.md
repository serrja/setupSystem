# Happ: установка и сохранение настроек

Happ владеет подписками, профилями маршрутизации и подключением. `setupSystem` проверяет пакет, делает приватную резервную копию и показывает состояние штатного автозапуска. Ссылки не входят в Git и не печатаются командами.

## 🚀 Установка

Единственная матрица платформ находится в [platforms.toml](../manifests/platforms.toml). Установщик принимает только Debian 12/13 на x86_64/arm64. Нужен `python3` версии 3.10+ для stdlib bootstrap; затем основной CLI использует отдельный Python 3.14. На текущем Ubuntu доступна только read-only диагностика: установка, импорт и восстановление через CLI остановятся как `UNSUPPORTED`.

```bash
python3 "$HOME/setupSystem/bootstrap.py" plan --profile happ
python3 "$HOME/setupSystem/bootstrap.py" apply --profile happ --yes
setup-system happ doctor
```

Установленный Happ не обновляется повторным запуском. Для отсутствующего клиента Debian зафиксирован официальный выпуск 4.5.4, SHA-256 каждого `.deb` и проверка метаданных пакета перед адресным `sudo apt-get install`. При недоступном `sudo` команда блокируется до скачивания. Работу выбранного пакета и GUI нужно отдельно подтвердить на Debian. Release digest не равен независимой подписи издателя.

## 🔒 Резервная копия и восстановление

На Debian закройте Happ обычным способом, только если это не оборвёт нужное соединение. Затем выполните:

```bash
setup-system happ backup
setup-system happ restore --backup BACKUP_ID
```

Копия находится в `${XDG_STATE_HOME:-$HOME/.local/state}/setup-system/backups/<id>/` с закрытым manifest. Она сохраняет `Happ.conf`, routing settings/cache и штатный autostart entry. SQLite подписок снимается через SQLite backup API с `integrity_check`, а не обычным копированием живой БД. Содержимое ссылок и правил остаётся только в приватной копии. Если Happ работает, backup блокируется; для работающего клиента предпочтителен штатный экспорт через его интерфейс.

Предпросмотр ничего не меняет. Для замены текущих файлов Happ должен быть закрыт, WAL/SHM отсутствовать, а конфликт должен быть просмотрен:

```bash
setup-system happ restore --backup BACKUP_ID --apply --yes --replaceCurrent
```

Перед заменой создаётся ещё одна приватная копия текущего состояния. Внутреннюю папку Happ нельзя считать переносимым экспортом: используйте совместимый штатный экспорт/импорт Happ; login registration и системные разрешения настраиваются отдельно. Не переносите идентичность устройства.

## 🔗 Подписки и отдельные конфигурации

Ссылка необязательна; пустой ввод пропускает импорт. Для одной или нескольких ссылок:

```bash
setup-system happ setup --yes --interactive
setup-system happ addSubscription
```

При наличии `wl-copy` или `xclip` CLI принимает ссылку скрыто в локальном терминале и передаёт её в системный буфер. В Happ используйте штатное добавление из буфера и проверьте результат в самом приложении до следующей ссылки. CLI очищает свой буфер после подтверждения, но менеджер истории может сохранить копию: для секретной ссылки безопаснее вводить её прямо в Happ. Если clipboard tool отсутствует, команда сообщает `needsManualAction` до запроса ссылки. Web-подписка, `happ://crypto…` и конфигурация классифицируются раздельно; содержимое не скачивается, не расшифровывается и не журналируется. При неизвестном результате сначала проверьте список Happ, а также совпадение имён. Подписка может менять настройки приложения.

## 🧭 Маршрутизация

```bash
setup-system happ configureRouting
```

Существующие правила, DNS, TUN и исключения остаются в Happ. В новых выпусках routing-профили принадлежат подпискам; управляемая JSON-подписка может запретить ручное изменение. `happ://routing/add/…` добавляет профиль, но первый профиль может стать активным после загрузки geo-файлов. `happ://routing/onadd/…` также активирует или заменяет профиль; CLI не передаёт такую ссылку автоматически. Совпадение имени может заменить профиль. Сохранение правил и их действие в текущем соединении различаются: [документация Happ](https://www.happ.su/main/dev-docs/routing) указывает на необходимость reconnect. CLI не переподключает VPN и не меняет fallback/DNS сам.

## ▶️ Штатный автозапуск

```bash
setup-system happ configureAutostart
setup-system happ doctor
```

На Debian команда читает настройку Happ и созданный самим приложением desktop entry. Если обе включены, результат `unchanged`; иначе включите запуск при входе в настройках установленной версии Happ и повторите проверку. Автоподключение и обновление подписок — отдельные параметры; CLI их не меняет. Регистрация entry не доказывает запуск после следующего входа, поэтому login-сценарий остаётся `needsManualCheck`.

## 🛠 Диагностика

`happ doctor` выводит только версию/источник, факт процесса, категории autostart/auto-connect/routing и число профилей. Он не подтверждает GUI, серверы, DNS/IPv6-защиту и отсутствие утечек. Для проверки плана используйте `setup-system plan --profile happ`. Не отключайте активный VPN ради обновления; новые правила, требующие reconnect, остаются отложенными до отдельного решения.
