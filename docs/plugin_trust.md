# 🔐 Plugin trust and administrative access

Previewing an HTTPS source reads release data or wheel metadata. The review identifies the author, source, stable compatible version, wheel closure, requested permissions and digest. The administrator can set `hosts` and trusted `digests` in root-owned `/etc/setup-system/plugin-sources.toml`. Use a digest obtained through an independently verified channel. Select the complete compatible binary release. Verification covers origins and redirects, wheel and expanded size, path collisions, entry points, dependencies and file identity. Source distributions cannot be installed through the extension dialog.

Activation requires uv, a compatible Python interpreter and the verified dependency closure. On Debian install uv through an approved administrative distribution channel before activating plugins. The manager stages a fresh backend environment, checks its metadata and worker, then switches the active generation. Running operations retain their own generation and approved release identity. Each environment isolates Python dependencies. Trusted extension code can access files available to the local user. [uv environments](https://docs.astral.sh/uv/pip/environments/)

Administrative actions require the identical Debian-installed plugin release and its protected resources under `/usr/lib/setup-system`. Declared permissions describe the request. The host verifies package ownership and release identity before prompting. Downloaded executable code stays outside the privileged path. An installed extension still needs explicit approval for each privileged plan.

Application startup permits read-only work. **Prepare administrative access** asks native sudo to validate the current interactive account. Its timestamp belongs to the terminal context. A privileged Apply can request authorization again. The Administration plugin separately prepares a selected existing local account using a reviewed native root operation. Passwords pass through the host's private terminal exchange. Inspect account, group and effective policy after the change. [Administrative access](administration.md)

The shared event stream records UTC time, severity, operation, plugin, action, phase, message code, outcome and bounded safe details. Retained JSONL files and the History tab contain structured events. Ownership and unresolved changes live in the private SQLite ledger. Routine logs omit native output, authentication material and full input payloads.
