# RTK для разработки

`setupSystem` закрепляет полную редакцию `rtk-ai/rtk` в `manifests/rtk.toml`. Это инструмент разработчика, а не зависимость Python-сервисов. Provider проверяет путь и версию до изменений и сохраняет уже подходящую установку. Upstream публикует SHA-256 архивов, но подпись релиза для закреплённой версии не установлена. Контрольная сумма подтверждает совпадение байтов с опубликованным списком, но сама по себе не подтверждает личность издателя.

## Установка и обновление

На новой поддерживаемой Debian-машине сначала выполните `setup-system rtk plan`, затем `setup-system rtk apply --yes`. Provider выбирает архив для архитектуры Linux, сверяет опубликованную сумму и исполняемый файл, делает backup прежнего бинарника и устанавливает новый атомарно в домашнем каталоге текущего пользователя. Для намеренной замены подходящего более старого бинарника используйте `setup-system rtk apply --update --yes`. Общая установка пакетов Debian остаётся отдельной командой.

## Проверка и использование

Выполните `setup-system rtk doctor`, `rtk --version` и `rtk gain --help`. Необязательная интеграция Codex — существующий hook `PreToolUse` в `~/.codex/hooks.json`, который запускает `rtk hook codex`; проверяйте фактическое переписывание команды установленными версиями. RTK может сокращать вывод. Для полной диагностики вызывайте исходную команду напрямую, например `/usr/bin/git diff --check`, и проверяйте её код выхода. Сокращённый вывод не доказывает успешность review, миграции, проверки секретов или CI.

Чтобы отключить интеграцию, после backup файла удалите только запись RTK hook из `~/.codex/hooks.json`, сохранив остальные hooks. `setup-system rtk restore --backup ID --yes` возвращает прежний бинарник, только если установленный файл не изменился. Локальная история и настройки RTK остаются на прежних пользовательских путях; provider их не удаляет. Терминальный профиль не запускает сетевой процесс.
