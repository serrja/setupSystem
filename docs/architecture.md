# Architecture

The Textual shell calls the application services created by `bootstrap.runtime`. The runtime holds one SQLite engine, shared HTTP client and task group. An operation keeps its generation leases and execution supervision when the user leaves its page.

The host discovers manifests through distribution metadata. A worker imports its own backend in the selected release environment. The provider broker resolves each action requirement and permits only its declared read and planning calls. Plugin settings select a provider explicitly when more than one candidate satisfies the contract.

A preview binds every step to an executor release and generation, handler, permissions, resources and preconditions. Apply repeats planning, reserves resources and invokes each handler in order. A separate readback records evidence before final verification and ownership updates. An uncertain result remains available for recovery.

The SDK ships as its own distribution. Each directory immediately under `plugins/` owns a package and its integrations. The host uses a protected execution record for privileged steps. Each platform package controls its own native launcher, installation and machine checks.
